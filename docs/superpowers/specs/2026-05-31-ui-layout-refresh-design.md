# UI 界面与功能布局调整设计文档

日期：2026-05-31
分支：`feature/ui-layout-adjustments`
项目：`stzh-h5-client`

## 1. 背景

当前 H5 客户端已经覆盖主要购物链路，包括首页、商品列表、商品详情、购物车、订单列表、订单详情、我的、船舶信息、登录和注册。

本次调整目标是优化 UI 界面和功能布局。已确认采用 **A 方案：主流商城清爽版**：

- 保留现有业务流程和后端接口契约。
- 让应用更接近主流移动商城的信息结构。
- 底部导航从 `首页 / 商品 / 订单 / 我的` 调整为 `首页 / 商品 / 购物车 / 我的`。
- 订单列表和订单详情继续保留，但订单入口降级到“我的订单”和下单成功后的详情链路。
- 统一页面层级、卡片、按钮、标签、表单和间距。

## 2. 设计目标

1. 强化主购物链路：`首页 -> 商品 -> 商品详情 -> 购物车 -> 提交订单`。
2. 将 `购物车` 放入底部一级导航，使入口符合主流商城习惯。
3. 将 `订单` 从底部导航移出，但保留在“我的订单”中，确保用户能查看历史订单。
4. 在不改变后端行为的前提下，统一整体视觉语言。
5. 控制实现风险，改动集中在 UI、路由配置和导航入口。

## 3. 非目标

- 不修改后端接口地址、请求字段或响应数据结构。
- 不调整订单状态流转规则。
- 不新增支付、优惠券、推荐算法、用户资料编辑等新业务。
- 不引入新的 UI 框架。
- 不移除订单列表页或订单详情页。
- 不重构与本次视觉调整无关的业务逻辑。

## 4. 导航设计

### 4.1 底部导航

当前底部导航：

```text
首页 / 商品 / 订单 / 我的
```

目标底部导航：

```text
首页 / 商品 / 购物车 / 我的
```

需要调整：

- 在 `src/pages.json` 的 `tabBar.list` 中，将 `pages/order/index` 替换为 `pages/cart/index`。
- 新增购物车 tab 图标。
- `pages/order/index` 仍保留在 `pages` 页面配置中，但不再作为 tab 页面。
- `pages/order/detail` 继续作为普通页面保留。

### 4.2 订单入口

订单继续通过以下路径进入：

- `我的 -> 我的订单`
- 下单成功后：`购物车 -> 订单详情`

由于订单不再是底部一级导航，“我的订单”入口需要保持清晰、易发现。

### 4.3 购物车入口

购物车成为一级 tab 页面。商品详情页中的“立即购买”在添加商品后应切换到购物车 tab。

目标行为：

```ts
uni.switchTab({ url: '/pages/cart/index' })
```

## 5. 视觉方向

整体采用清爽移动商城风格：

- 浅灰页面背景。
- 白色卡片承载内容。
- 保留橙红主色，用于价格、主按钮、选中态、关键标签。
- 降低大面积渐变的使用频率。
- 渐变只保留在小型品牌强调或关键区域，不再作为全页面主要视觉。
- 标题层级更紧凑，商品信息更利于扫描。
- 卡片、按钮、表单、标签的圆角和间距保持一致。

视觉重点不是做营销型首页，而是让用户更快完成浏览、加购和下单。

## 6. 设计变量

继续使用 `src/styles/theme.scss` 作为设计变量来源。

建议使用规则：

| 用途 | 变量 |
|------|------|
| 主操作按钮 | `$brand-primary` |
| 商品价格 | `$text-price` |
| 可配送/成功态 | `$secondary-green` |
| 页面背景 | `$bg-page` |
| 卡片背景 | `$bg-card` |
| 卡片边框 | `$border-color` |
| 分割线 | `$divider-color` |
| 标准圆角 | `$radius-md` |
| 小圆角 | `$radius-sm` |
| 页面横向间距 | `$space-lg` |
| 卡片内边距 | `$space-md` |

如需新增公共样式，应优先放在 `src/styles/common.scss`，且只添加可跨页面复用的样式。

## 7. 页面设计

### 7.1 首页

定位：让用户快速进入搜索、分类和推荐商品。

目标结构：

1. 品牌头部：
   - 品牌名。
   - 简短说明：保税仓商品配送到船。
   - 小型配送/保税仓标签。
2. 搜索条：
   - 全宽圆角。
   - 点击进入商品页。
3. 分类宫格：
   - 最多展示 8 个分类。
   - 4 列布局。
   - 图标或 emoji 尺寸统一。
4. 推荐商品：
   - 双列商品卡。
   - 展示图片/占位图、名称、规格、价格、配送标签。

实现约束：

- 保留现有 `getCategories()` 和 `getProducts({ page: 1, page_size: 6 })` 调用。
- 保留首页分类跳转商品页的逻辑。
- 减少过大的装饰性 banner 对首屏的占用。

### 7.2 商品列表页

定位：高效浏览和筛选商品。

目标结构：

1. 顶部 sticky 搜索条。
2. 横向分类 tab。
3. 商品列表卡片。
4. 商品卡片展示：
   - 图片/占位图。
   - 商品名称。
   - 规格。
   - 价格。
   - 库存。
   - 保税仓/可配送标签。

实现约束：

- 保留现有分类扁平化逻辑。
- 保留关键词搜索逻辑。
- 本次不新增分页加载能力。

### 7.3 商品详情页

定位：提供商品确认信息，并促进加购/购买。

目标结构：

1. 大图区域。
2. 商品摘要卡片：
   - 商品名称。
   - 价格。
   - SKU。
   - 库存与无人机配送状态。
3. 规格卡片：
   - 重量、体积、规格、来源。
4. 商品说明卡片。
5. 底部固定操作栏：
   - 次按钮：加入购物车。
   - 主按钮：立即购买。

实现约束：

- 保留现有加购逻辑。
- 购物车成为 tab 后，“立即购买”添加商品后切换到购物车 tab。

### 7.4 购物车页

定位：作为一级 tab 页面，承载商品确认和下单。

目标结构：

1. 页面头部：
   - 标题：购物车。
   - 商品数量。
2. 购物车商品卡片：
   - 图片。
   - 名称、SKU。
   - 单价。
   - 数量步进器。
   - 删除入口。
3. 订单试算区域：
   - 商品金额。
   - 总重量。
   - 总体积。
   - 交易模式标签。
   - 试算原因说明。
4. 收货信息区域：
   - 收货人。
   - 舱房号。
   - 联系方式。
   - 备注。
5. 底部结算栏：
   - 应付金额。
   - 提交订单按钮。

实现约束：

- 购物车作为 tab 页后，需要处理底部 tabBar 和固定结算栏的安全间距。
- 空购物车状态需要提供明确的“去商品页”行动入口。
- 保留下单逻辑，不改后端参数。

### 7.5 我的页

定位：账户、船舶信息和次级业务入口。

目标结构：

1. 用户摘要：
   - 头像首字母。
   - 昵称/用户名。
   - 当前船舶标识。
2. 船舶信息卡片：
   - 船名或船号。
   - 船籍、IMO、MMSI。
3. 功能宫格：
   - 我的订单。
   - 船舶信息。
   - 扫码收货。
   - 个人资料占位。
4. 设置列表：
   - 语言切换。
5. 退出登录按钮。

实现约束：

- “我的订单”应比当前更容易识别，因为订单不再在底部导航中。
- 扫码收货本次只保持现有行为，不接入新的收货接口。

### 7.6 订单页面

定位：保留订单查询能力。

目标：

- 订单列表页和订单详情页继续可用。
- 允许做轻量视觉统一。
- 不调整订单筛选逻辑、分页逻辑或接口调用。

## 8. 组件与样式策略

继续复用现有组件：

- `AppEmpty`
- `AppSkeleton`

本次不建立大型设计系统。只有在两个以上页面复用时，才新增公共样式。

候选公共样式：

- 页面头部。
- 区块标题。
- 卡片基础样式。
- 标签/徽标。
- 价格文本。
- 主按钮/次按钮。

避免为了视觉调整过度拆分组件。

## 10. 功能行为变化

本次预期行为变化：

1. 底部导航 `订单` 改为 `购物车`。
2. 点击购物车 tab 进入 `pages/cart/index`。
3. 商品详情“加入购物车”保持原行为。
4. 商品详情“立即购买”添加商品后进入购物车 tab。
5. “我的订单”继续进入订单列表。
6. 订单详情跳转保持不变。

不改变任何后端行为。

## 11. 响应式与可用性要求

目标平台是移动 H5/uni-app。

要求：

- 卡片和按钮中的文本不能明显溢出。
- 商品卡片图片比例稳定。
- 底部固定栏不能遮挡表单内容。
- 表单输入框保持易点击。
- 空状态需要明确下一步操作。
- 中英文文案都应尽量避免被截断。

## 13. 风险与应对

风险等级：中低。

主要风险：

- tabBar 页面调整后，跳转到购物车的代码需要使用 `switchTab`。
- 购物车成为 tab 页后，固定结算栏可能和原生 tabBar 间距冲突。
- 缺失购物车 tab 图标会导致构建或运行时资源加载异常。
- 测试人员可能仍习惯从底部进入订单，需要明确订单入口已移动到“我的订单”。

应对方式：

- 保留订单页面注册。
- 只更新明确指向购物车的导航点。
- 先新增购物车图标，再修改 `pages.json`。
- 实现后运行类型检查和 H5 构建。
